# Экосистема плагинов

## Порядок работы

1. Прочитать текущий проект и AGENTS.md. Найти существующий контракт до изменения структуры; не создавать второе ядро вместо обновления первого.
2. Завершать и проверять текущий этап до следующего. Задавать по одному существенному вопросу, только если ответ блокирует работу.
3. Прочитать [plugin-contract.md](references/plugin-contract.md) и [core-architecture.md](references/core-architecture.md). Для внешних интерфейсов прочитать [openai-compat.md](references/openai-compat.md) и [mcp-expose.md](references/mcp-expose.md).
4. Использовать один реестр инструментов и один диспетчер с проверкой прав, аргументов, результата и повторов. Экспорты не должны содержать второй экземпляр бизнес-логики.
5. Перед реализацией SDK, OAuth и подключений проверять первичные источники и версии библиотек. Не выводить возможности клиента из плейсхолдера URL или слова SSE.
6. Для нового домена запустить `bash <skill-dir>/scripts/new-plugin.sh <domain> <project-root>`, затем `bash <skill-dir>/scripts/check-tools.sh <project-root>/plugins/<domain>`. Использовать явные абсолютные пути. Не перезаписывать существующий домен.
7. Реализовать порты регистрации через официальный MCP SDK и выбранный HTTP-фреймворк. Не выдавать произвольный JSON/SSE за MCP. Закрывать неавторизованный доступ до подключения данных.
8. Проверять межорганизационный доступ, конкурентные повторы, неверные аргументы и смешение версий проверок. После появления сервера проверять настоящий протокол, а не только HTTP GET.
9. Сообщать отдельно: реализовано, проверено, спроектировано, остаётся до внешнего подключения. Не называть заготовку развёрнутым сервером.

## Принятые требования

- Владелец загружает данные Plaud пакетно раз в 3–5 дней. Не навязывать постоянную синхронизацию, CLI или замену приложения.
- Формат входа пока не выбран. Нормализовать его отдельным адаптером; не обещать поддержку любого файла без парсера и образца.
- Сохранять исходники, версии и связи результатов с источниками в границах организации.
- Выполнять четыре проверки: полнота; точность относительно исходников; согласованность внутри пакета и с историей; итоговая подтверждённость.
- Публиковать проверенные результаты только после четырёх успешных проверок текущей версии. Показывать промежуточные статусы и ошибки отдельно.
- Предусмотреть домены meetings, tasks, documents, finance. Не считать их бизнес-логику уже реализованной.
- Считать MCP обязательным. Основной адрес `/{domain}/mcp`; `/{domain}/mcp/sse` — отдельный режим совместимости, а не обязательный суффикс.

## Граница комплекта

Комплект содержит контракт, архитектуру, шаблоны Python-плагина и адаптеры регистрации. Генератор создаёт диагностический инструмент и описание маршрутов. Веб-сервер, OAuth, PostgreSQL, четыре ИИ-проверки и кабинет этим комплектом не запускаются.

`expose/mcp.py` передаёт схемы и обработчик в порт ядра; это не реализация транспорта. `expose/openai.py` экспортирует function calling для Responses и Chat Completions; это не модельный сервер.

`scripts/mcp-check.sh` предназначен для настоящего сервера: проверяет выбранный профиль Streamable HTTP и при явном указании вызывает инструмент без побочных эффектов. Legacy HTTP+SSE проверять официальным SDK/Inspector.

## Ресурсы

- `references/plugin-contract.md`: tools, handle, контекст, ошибки, регистрация, данные.
- `references/core-architecture.md`: БД, пакетная обработка, четыре проверки, Make.com.
- `references/openai-compat.md`: оба формата function calling и пределы совместимости.
- `references/mcp-expose.md`: версии протокола, авторизация, проверка клиентов.
- `assets/plugin-template/`: шаблоны без сетевого сервера и секретов.
- `scripts/new-plugin.sh` и `new_plugin.py`: создание заготовки.
- `scripts/check-tools.sh` и `check_tools.py`: проверка контракта и экспортов.
- `scripts/mcp-check.sh` и `mcp_check.py`: ограниченная проверка реального сервера.

## Создать новый проект

Запустить `bash <repo>/scripts/new-ecosystem.sh <domain> /absolute/new-project`.
Без второго аргумента создаётся `./ecosystem`. Родитель должен существовать;
существующий каталог назначения, включая пустой, не перезаписывается.
Генератор переносит текущее локальное ядро, контракт и зависимости и создаёт первый
диагностический домен. БД/HTTP/OAuth/кабинет не запускаются. Для уже существующего
проекта использовать new-plugin.sh, не new-ecosystem.sh.
