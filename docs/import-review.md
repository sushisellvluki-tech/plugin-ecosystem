# Объединение загруженного комплекта

Источник: plugin-ecosystem.zip; SHA-256: `d89ef514fac9437e11e718e30658cd3e596d3104863b02cde37b9606598ab40c`.

## Проверено на исходном архиве

- new-ecosystem.sh перезаписывает core/__init__.py существующего проекта.
- check-tools.sh для созданного meetings завершается с `name 'name' is not defined`.
- new-plugin.sh принимает bad-name, но генерирует невалидный Python.
- Новый класс Plugin использует sync handle, success/data/error и обёртку OpenAI;
  текущий контракт использует async handle, ToolSpec, ok/data/error/warnings.
- Из четырёх проверок в архиве реализован лишь пример CompletenessCheck.
- Нет БД, миграций, работающего MCP/HTTP host, OAuth, Plaud-парсера или кабинета.

## Решение

Сохранён существующий контракт и проверенное ядро. new-ecosystem.sh адаптирован:
копирует это ядро и вызывает текущий генератор, отказывает при существующем назначении.
Сохранены текущие new-plugin.sh и check-tools.sh. Пять новых reference адаптированы
с сохранением тем Item/Event, четырёх проверок, кабинета, Plaud и рецептов доменов.
MCP reference сохранён; итог — девять reference. Общие документы не заменены
несовместимыми версиями из архива. Текущий путь генерации не импортирует старое ядро.

В документах устранены: публикация active по умолчанию; подмена проверки точности
самим извлечением; глобальный поиск событий; неподтверждённая CLI-команда Plaud;
обещание автоматически работающих endpoints. Сохранён пакетный приём раз в 3–5 дней.

Работа касается репозитория GitHub; установленная персональная копия навыка
этим коммитом автоматически не обновляется.
