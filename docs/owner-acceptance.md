# Совместная проверка с владельцем фирмы

Экспорт пока не запрашиваем. Сначала завершаем синтетический нагрузочный прогон.
Затем проводим короткую совместную проверку на известном владельцу материале.
Ни одно сообщение или запрос владельцу автоматически не отправляется.

## Перед передачей материала

Оператор объясняет владельцу, что уже работает: хранение текстовых расшифровок,
версии, ссылки на цитаты, отдельное подтверждение и запрет публикации без проверок.
Нативный парсер Plaud и автоматическое ИИ-извлечение пока не подключены.
Для следующего этапа выберем доступный владельцу формат экспорта по его образцу.
Не просим менять приложение или заводить постоянную синхронизацию.

До реальных записей определяем, где они будут храниться, кто имеет доступ и как
их удалить. Для первого сеанса подходит обезличенный материал. Для совместного сеанса используем [кабинет](cabinet.md): загрузку, исходники,
цитаты и отдельную проверку. API/MCP остаются доступными оператору.

## Приёмочный набор — когда владелец будет готов

Достаточно нескольких коротких записей, содержание которых он хорошо помнит:

1. Обычная встреча с ясными решениями и поручениями.
2. Та же запись повторно — проверка дублей.
3. Исправленная версия — проверка сохранения старого текста и устаревания проверок.
4. Неоднозначный срок или спорное поручение — проверка блокировки и уточнения.
5. Неподдерживаемый/пустой элемент рядом с нормальным — ошибка должна быть видна.

Владелец заранее записывает ожидаемые решения, ответственных и сроки. Эта заметка
служит контрольным ответом при приёмке, а не подставляется вместо содержимого записи.

## Что показываем в сеансе

| Действие | Ожидаемый наблюдаемый результат |
|---|---|
| Принять пакет | Каждая запись видна: принята, дубль или отклонена с причиной |
| Открыть исходник | Текст совпадает с переданным материалом |
| Предложить факт | Есть точная цитата и позиция; предложение ещё не считается проверенным |
| Указать неверную цитату | Публикация заблокирована, замечание объяснено |
| Исправить источник/черновик | Новая версия; старые подтверждения не разрешают новую публикацию |
| Подтвердить другим пользователем | Сохраняются проверяющий, основание и результаты проверок |
| Опубликовать и повторить запрос | Одна публикация и одно событие, без повторных эффектов |

Сейчас факты формируются вручную либо внешним клиентом; собственный ИИ-конвейер не
выдаём за готовый. Его качество будем оценивать отдельно по контрольным ответам
после выбора модели и подключения извлечения.

Фиксируем расхождения, ID пакета/run, ожидаемый результат и фактический результат.
Не включаем токены и полные разговоры в публичные GitHub issues или отчёты.
Критерий завершения сеанса — все записи учтены, ошибки объяснены, исправления
прослеживаются, неподтверждённое не опубликовано. Оценка скорости — отдельный замер.
