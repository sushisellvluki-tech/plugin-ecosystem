# Кабинет встреч

Кабинет встроен в существующий сервер и открывается по `/cabinet`.
Он вызывает тот же реестр и диспетчер, что HTTP/MCP-клиенты. Прямой записи в БД
из интерфейса нет; интерфейс не заменяет серверную проверку прав и актуальности.

## Запуск

Установите зависимости и примените миграции по [postgres.md](postgres.md).
В конфигурации сервера включите `plugins.meetings.plugin`, задайте ключи доступа,
`allowed_hosts` и `DATABASE_URL` по [server.md](server.md). Запускайте без `--demo`.

```bash
python -m server --config /absolute/path/server.json
```

Откройте `http://127.0.0.1:8000/cabinet`. Публичное развёртывание этим действием не
выполняется. При внешнем HTTPS-прокси явно добавьте его origin в `allowed_origins`
и домен в `allowed_hosts`; заголовки прокси автоматически не считаются доверенными.

Оболочка и локальные JS/CSS общедоступны, но не содержат записей организации.
Все данные требуют Bearer-ключ. Ключ вводится в поле пароля, очищается после входа
и хранится только в памяти вкладки: без cookies, localStorage/sessionStorage и URL.
Перезагрузка требует нового входа. Это доступ для пилота, не полноценная OAuth-форма
входа или система выдачи ключей. Администратор выдаёт ключи вне кабинета.

## Рабочий сценарий

1. **Автор:** войти, загрузить TXT-файлы UTF-8 или вставить текст. Указать источник,
   при наличии — стабильный ID каждой записи. Видны дубли и ошибки приёма.
2. **Черновик:** добавить факт, выбрать запись и точную цитату, сформулировать смысл,
   предмет и значение. При нескольких совпадениях выбрать нужное место цитаты.
   Подсветка показывает контекст. Unicode-позиции учитывают символы вне BMP, например emoji.
3. **Проверяющий:** войти другим пользователем, открыть исходники и историю,
   подтвердить точность, полноту и согласованность с обоснованием либо вернуть замечания.
4. **Публикующий:** открыть актуальную проверенную версию и подтвердить публикацию.
   Устаревшие подтверждения и неуспешные проверки не разрешают публикацию.

Права в БД и токене должны совпадать с задачами пользователя:

| Пользователь | Права |
|---|---|
| Автор | `meetings:read meetings:write` |
| Проверяющий | `meetings:read meetings:review` |
| Публикующий | `meetings:read meetings:publish` |

Автору можно также дать право публикации, но проверяет его черновик другой actor.
Кнопки скрываются по правам и состоянию; окончательное решение всегда за сервером.

## Ограничения и сохранность

- До 20 записей и 32 КиБ текста в пакете; общий лимит JSON-аргументов — 64 КиБ.
- Только TXT UTF-8 / вставленный текст. PDF, ZIP и аудио не преобразуются скрыто.
- Создание фактов пока ручное; автоматическое ИИ-извлечение не подключено.
- Список пакетов имеет курсорные страницы по 20 записей; счётчик показывает загруженные
  строки списка, а не общий объём организации. API допускает страницы от 1 до 50.
- После сетевого сбоя/503 неизменённый повтор получает прежний ключ идемпотентности
  в этой вкладке. После закрытия вкладки ключ не сохраняется: сначала проверьте список
  пакетов перед повторной загрузкой. Несохранённый черновик также не переживает закрытие.
- При выходе очищаются исходники, формы, история и ключи; текущие запросы отменяются,
  ответы старой сессии не заполняют новый кабинет. Уже принятая сервером запись может
  завершиться после отмены клиента — это не откат серверной транзакции.
- Данные источника вставляются текстовыми DOM-узлами, а не HTML. Нет внешних CDN,
  аналитики и сторонних скриптов. CSP запрещает встраивание страницы и inline-скрипты.
- Собственный origin разрешён только при совпадении со схемой/Host, проверяемым
  внешним TrustedHostMiddleware; посторонние origin остаются запрещены.

Кабинет показывает текущую версию пакета и историю публикаций. История всех
неопубликованных черновиков, редактирование состава существующего пакета, поручения
как отдельные сущности и процессы удаления/хранения — отдельные этапы.

## Проверка браузером

При одноразовой тестовой БД из `docs/postgres.md`:

```bash
npm install --no-save playwright@1.62.1
npx playwright install --with-deps chromium --only-shell
node scripts/cabinet_browser_test.mjs
```

Сценарий создаёт синтетические учётные записи, запускает настоящий Uvicorn и Chromium,
загружает TXT, сохраняет цитату после emoji, проверяет независимую оценку и публикацию,
смену организации, отсутствие постоянного хранения ключа, буквальное отображение HTML
в исходнике и мобильную ширину. Один ответ 503 подменяется только для проверки
повторного ключа в UI; отказ/откат БД отдельно проверен настоящим интеграционным тестом.

Проверено в [CI 36925019712](https://github.com/sushisellvluki-tech/plugin-ecosystem/actions/runs/36925019712):
62 теста без пропусков, повторный нагрузочный прогон 1008 вызовов и полный
браузерный сценарий на PostgreSQL. Снимки desktop/mobile проверены визуально.
Это проверка синтетического пилота; публичный сервер и реальные учётные записи
владельца данным этапом не создавались.
