# Item + Event: проект хранения

Статус: базовое PostgreSQL-хранилище и миграция 001 реализованы в core/db.
Инструкция подключения — [docs/postgres.md](../docs/postgres.md).
Ниже целевая модель: версии источников, публикация и полный набор проекций
ещё требуют последующих миграций; фактические поля определяет 001_initial.sql.
Применять вместе с [контрактом](plugin-contract.md) и [архитектурой](core-architecture.md).

## Item

Общий индекс результатов доменов: organization_id, id, domain, kind, status,
revision, created_by, created_at, updated_at, meta JSONB, source_version_id.
Начальный статус — raw/ingested, а не active. Проверенный результат становится
published только после публикационного барьера текущей версии.

Item — общая проекция, не замена всем доменным моделям. Ответственные, сроки,
денежные суммы, связи и поля для ограничений/поиска хранятся типизированно.
JSONB предназначен для изменчивых метаданных с schema_version и валидацией.
Изменение JSON-формата также требует стратегии совместимости и иногда миграции данных.

## Event

Неизменяемый журнал: organization_id, id, domain, kind, item_id, item_revision,
actor_id, request_id, occurred_at, payload, payload_schema_version.
Связь с Item — составной FK (organization_id, item_id), а не только item_id.
Не копировать полный транскрипт, ключи или персональные данные в каждое событие.
Исправление создаёт новую версию/событие, не переписывает историю.

## Изоляция и доставка

- Tenant context формируется после аутентификации и проверки членства.
- Все запросы Item/Event требуют организацию и доменные scopes; отсутствие
  organization_id не означает «прочитать все организации».
- Составные FK/уникальности, RLS и transaction-local tenant дополняют авторизацию.
- Изменение, результат идемпотентной операции и outbox записываются одной транзакцией.
- Event-журнал не является надёжной очередью сам по себе. Outbox worker доставляет
  события с ограниченными повторами; consumer подавляет дубли по event_id и организации.
- Междоменные операции идут через сервисы ядра/события. Подписка не даёт права на чужие данные.

## Индексы и миграции

Планировать индексы (organization_id, domain, kind, status),
(organization_id, occurred_at, id) для курсорной пагинации Event,
(organization_id, item_id, item_revision). GIN на JSONB добавлять под реальные запросы.
У каждого домена свои schema/миграции; общий граф миграций проверяет порядок зависимостей.
При переходе на БД добавить тесты двух организаций, отката транзакции,
конкурентной идемпотентности, восстановления outbox и запуска с ролью без BYPASSRLS.
