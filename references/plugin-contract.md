# Контракт плагина v0.1

Содержание: границы; ToolSpec; контекст; результат; БД; порты; готовность.

## Границы и интерфейс

Плагин владеет логикой и схемой данных домена. Ядро владеет идентификацией, правами, диспетчеризацией, миграциями, очередью и транспортами. Все способы вызова проходят одинаковые проверки.

```python
def tools() -> list[dict]: ...
async def handle(name: str, arguments: dict, context: dict) -> dict: ...
```

`tools()` возвращает новые JSON-совместимые описания без БД/LLM. `handle()` вызывается только из диспетчера. Не копировать вручную схемы наружных интерфейсов.

## ToolSpec

| Поле | Правило |
|---|---|
| name | `domain__action`, ASCII `[a-z][a-z0-9_]*`, максимум 64 символа, уникально в ядре |
| description | Когда вызывать, что возвращает, ограничения |
| input_schema | Объект JSON Schema; переносимое подмножество: все поля required, nullable для отсутствующего значения, additionalProperties=false |
| output_schema | Схема успешного поля data, объект в корне |
| required_scopes | Непустой список прав, например meetings:read |
| read_only | Нет изменения данных и внешних действий |
| idempotent | Семантика, которую должен обеспечивать обработчик/ядро |
| destructive | Признак удаления/необратимого действия |
| open_world | Возможность взаимодействия с внешней системой |

Неподдержанную схему отклонять при сборке. Не снимать ограничения автоматически и не объявлять strict=true без проверки.

## Доверенный контекст и диспетчер

```json
{"organization_id":"org-example","actor_id":"user-example","scopes":["meetings:read"],"request_id":"server-generated","idempotency_key":null}
```

Контекст формирует ядро после аутентификации и проверки членства. Tenant и права не брать из аргументов модели, текста встречи или непроверенного заголовка. Выбор организации проверять по членству; session ID не является tenant ID.

Порядок диспетчера:

1. Проверить identity, organization, членство, доступность домена, scopes.
2. Найти инструмент, проверить JSON Schema аргументов и лимит размера.
3. Для записи атомарно резервировать `(organization,operation,idempotency_key)` с хешем аргументов. Тот же ключ с другим телом даёт CONFLICT; конкурирующий повтор не запускает второй эффект.
4. Передать handler доверенный контекст и tenant-scoped repository.
5. Проверить результат; сохранить изменение, идемпотентный результат и outbox-событие в одной транзакции, где применимо.
6. Записать аудит без токенов/полных разговоров; вернуть результат через адаптер.

Фильтрация каталога не заменяет авторизацию вызова. Проверять права также при поиске, чтении записи, скачивании файла и получении job status. Model annotations и client allowed_tools не являются средствами авторизации.

## Результат

```json
{"ok":true,"data":{"job_id":"example","status":"queued"},"error":null,"warnings":[]}
```

При ошибке: ok=false, data=null, error={code,message,retryable}. Не возвращать пустой успех вместо «не реализовано» или ошибки БД. Трассировки остаются в защищённом журнале.

| Код | HTTP | Политика |
|---|---|---|
| UNAUTHENTICATED | 401 | Исправить авторизацию |
| FORBIDDEN | 403 | Нужны права |
| INVALID_ARGUMENT | 400 | Исправить вход |
| NOT_FOUND | 404 | Не раскрывать чужие объекты |
| CONFLICT | 409 | Разрешить конфликт |
| NOT_IMPLEMENTED | 501 | Требуется реализация |
| RATE_LIMITED | 429 | Ограниченный повтор по Retry-After |
| DEPENDENCY_UNAVAILABLE | 503 | Ограниченный повтор с задержкой |
| INTERNAL_ERROR | 500 | По политике операции |

MCP протокольные ошибки и ошибки выполнения инструмента различать; не отображать все ошибки в HTTP 500. MCP success структурирует data, а OpenAI function output сериализует весь ToolResult.

## Данные

Для рабочего ядра: PostgreSQL, общая БД и собственная schema/миграции каждого домена. Это владение данными, а не отдельный сервер на каждый плагин. Физическое разделение позднее сохраняет repository/service интерфейсы.

В tenant-таблицах: organization_id, id, created_at, updated_at; время UTC/timestamptz. Уникальность `(organization_id,id)` и составные FK с organization_id исключают связи с чужой организацией. Авторизацию приложения дополнить RLS; роль BYPASSRLS не считать защищённой политиками. При пуле соединений tenant устанавливать transaction-local.

Не писать напрямую в таблицы другого плагина. Использовать его сервис/события и стабильные ID. JSONB — для raw-ответов и изменчивых метаданных, а не замена всех нормализованных сущностей.

## Порты регистрации

Это собственные интерфейсы будущего ядра, не API стороннего SDK:

```python
host.add_json_get(path, handler)   # await handler(trusted_context) -> JSON
host.add_json_post(path, handler)  # await handler(body, trusted_context) -> JSON
host.add_mcp_endpoint(
    path=path,
    list_tools=list_handler,       # await list_handler(context) -> list[dict]
    call_tool=call_handler,        # await call_handler(name,args,context) -> MCP result
    legacy_sse_path=None,
)
await dispatch(plugin, tool_name, arguments, trusted_context)
```

Host обязан установить auth, преобразовать протокольные ошибки, управлять SDK и жизненным циклом. OpenAI адаптер регистрирует `/{domain}/v1/tools` и `/{domain}/v1/tools/invoke`; MCP — `/{domain}/mcp`. Legacy включает отдельный transport и обратный POST SDK. endpoint-plan.json описывает будущую регистрацию, а не запущенную службу.

## Готовность

Для заготовки: импорт, уникальные имена, совпадение экспортов, фильтрация scopes, отказ неизвестному вызову, отсутствие перезаписи при повторе генератора.

Для рабочего домена дополнительно: миграции, tenant/конкурентные тесты, атомарная идемпотентность, реальная логика, HTTP/OAuth runtime, проверка официальным MCP-клиентом. Первый набор не заменяет второй.
