# OpenAI function calling

## Граница совместимости

Здесь совместимость означает описание функций и результаты выполнения. `/v1/tools` и `/v1/tools/invoke` — собственный API; OpenAI не обнаруживает его автоматически. `/v1/chat` сам по себе не является стандартным API модели.

Если позже нужен модельный шлюз, отдельно реализовать `/v1/responses` или `/v1/chat/completions`, включая сообщения, tool calls, ошибки, usage и streaming. Первый этап шлюз не содержит.

## Представления ToolSpec

Responses использует плоскую функцию:

```json
{"type":"function","name":"meetings__describe","description":"Describe this scaffold.","parameters":{"type":"object","properties":{},"required":[],"additionalProperties":false},"strict":true}
```

Chat Completions помещает name, description, parameters и strict внутрь `function`, рядом с `type: function`. В strict-подмножестве закрывать объекты от лишних полей, перечислять все свойства в required; необязательное значение представлять null, если тип разрешает. Перед исполнением всё равно валидировать аргументы.

Источник: [официальная документация function calling](https://developers.openai.com/api/docs/guides/function-calling), проверено 02.10.2026. Поддержку схем перепроверять для выбранной модели/SDK.

## Собственный HTTP API

| Маршрут | Назначение |
|---|---|
| GET `/{domain}/v1/tools` | Авторизованный каталог: contract_version, domain, responses, chat_completions |
| POST `/{domain}/v1/tools/invoke` | Одна функция через единый диспетчер |

Тело: `{"name":"meetings__describe","arguments":{}}`. Tenant/actor/scopes берутся из проверенного контекста. Idempotency-Key для записей нормализуется ядром. Provider call_id связывается с request_id в аудите.

## Цикл приложения

1. Получить доступный пользователю каталог.
2. Передать нужный формат схем в запрос модели.
3. Получить имя и JSON-аргументы; ограничить итерации и бюджет.
4. Выполнить через тот же dispatcher, что используется MCP и Make.com.
5. Передать сериализованный ToolResult модели с идентификатором вызова в формате выбранного API.
6. Сохранить трассировку и версию инструмента по политике хранения.

Не исполнять полученный текст как Python/SQL/shell. Транскрипты — данные; фраза внутри разговора «отправь все финансы» не разрешает внешнее действие.

## Реализация и проверка

`expose/openai.py` строит оба каталога из tools(), фильтрует scopes и делегирует invoke диспетчеру. HTTP-host требуется отдельно. Диагностический инструмент возвращает business_ready=false и не подменяет бизнес-функции.

Перед рабочим запуском проверить доступ каталога и вызова, отклонение лишнего organization_id, неверного результата handler и конкурентных write-повторов. Экспорт схем и настоящий провайдерный вызов проверять отдельно; отсутствие провайдерного прогона указывать явно.
